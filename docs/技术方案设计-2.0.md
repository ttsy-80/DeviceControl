## 1. 总体架构（不变部分）

```
┌─────────────┐     ViewBinding      ┌──────────────────────┐
│  Activities │ ◄──────────────────► │ ViewModels           │
│  (UI 层)    │   LiveData / 点击    │ TaskControlViewModel │
└─────────────┘                      │ Model* / Task* VM    │
        │                              └──────────┬───────────┘
        │                                         │
        │                              ┌──────────▼───────────┐
        │                              │ Repository + Room    │
        │                              └──────────┬───────────┘
        │                                         │
        └──────────────────────────────────────────┼──────────────────┐
                                                   ▼                  │
                                        ┌──────────────────┐         │
                                        │ SlcanManager     │◄── USB │
                                        │ CANOpenHelper    │   VCP   │
                                        └──────────────────┘         │
```

- **app**：入口 `MainActivity` 与各业务 Activity 路由。  
- **engine-lib**：型号、任务、控制、通讯、资源与主题。

**2.0 增量**：在架构上增加「设置域」（蓝牙/语言/升级/关于）、「首页三入口」、检测页 **三栏布局** 与 **蓝牙连接状态** 的全局状态源；通讯层可扩展 **BLE** 或沿用 **USB VCP**（产品定稿后二选一或并存）。

## 3. 全局状态与导航

### 3.1 连接状态（顶栏）

- **数据源**：USB 已枚举且协议握手成功 → `已连接`；否则 `未连接`。若接蓝牙，则 BLE GATT 连接态合并同一 `ConnectionState`（`Sealed class` 或 `LiveData`）。  
- **消费方**：所有含顶栏的页面订阅同一 `ConnectionStateRepository`，避免各页自行判断不一致。

### 3.2 时间/日期

- 系统时钟 + `BroadcastReceiver`（`TIME_TICK`）或每分钟刷新；与 PDF 格式 `HH:mm:ss`、星期 + `yyyy/MM/dd` 对齐。

## 4. 任务控制技术要点（现有实现，迁移时保留语义）

### 4.1 协程与 Job

- `jogJob`：点动/连续循环；暂停、切换子任务前 `cancelAndJoin()`。  
- 连续模式在 `Dispatchers.IO` 发 CAN；读 Room 回主线程。

### 4.2 指令映射

- `EngineControlCommand` → `TaskControlViewModel.requestsForCommand` → `List<SlcanRequest>`。  
- `sendCommandThenPersist`：成功再更新 LiveData + Room。

### 4.3 连续模式算法（现状）

- `delayContinuousRevolutionSlice`：按「秒/圈」墙钟模拟圈进度；50ms 步进读速；圈数 Toast 等逻辑保持，直至 UI 改为真实编码器进度（可选后续项）。

### 4.4 子任务切换与记录

- 与现有 `switchToTask`、`TaskRecord` 入库、`readPosition` 流程一致；**表头列名与按钮文案**按 PDF 调整仅影响 UI 层。

### 4.5 日志

- `EngineLog` + `DebugLogHolder`；关键路径在 ViewModel / Activity 打点。

## 5. 数据模型与 PDF 字段映射（重点）

### 5.1 现有 `TaskExecution`（摘要）

- `speed`：**秒/圈**（界面曾用「分钟/圈」×60 写入）。  
- `operationMode`：`JOG` / `CONTINUOUS`。  
- `continuousCycles`、`jogInterval`、`speedStep`、`playbackSpeed` 等。

### 5.2 PDF 稿面单位与控件（P8、P11）

稿面出现 **°/秒、S、片** 等与当前「分钟/圈、秒」并存。技术策略：

| 稿面概念 | 建议域模型 | 与现有映射 |
|----------|------------|------------|
| 自动点动角度 / 手动点动角度 | `jogAngleDegrees` 或沿用角度字段 | 与 CAN 位置模式指令对齐；缺省用现有点动步进 |
| 基础点动速度、自动连续速度、手动连续速度 | 统一内部 **度/秒** 或 **秒/圈** 存一 canonical | UI 层换算；持久化只存 canonical，避免双单位脏写 |
| 点动停滞时间 | 秒，可与 `jogInterval` 合并或分字段 | 产品确认后扩展 Room migration |
| 自动多转数 | 与 `continuousCycles` 对齐 | 直接映射 |
| 叶片数 / 位置 | 已有 `TaskRecord`、型号表 | 列展示对齐 PDF |

**原则**：Room 层单一单位；**换算在 ViewModel + 设置 UI**；迁移脚本版本化。

### 5.3 新模式枚举（若产品确认稿面「自动/手动」≠ 点动/连续）

- 方案 A：`operationMode` 拆为 `AUTO | MANUAL`，子维度仍为 `JOG | CONTINUOUS`。  
- 方案 B：保留 `JOG/CONTINUOUS`，用 `uiMode: AUTO_MANUAL` 仅影响参数面板与默认速度来源。  
落地前在评审会二选一并写入需求变更单。

## 6. 通讯与异常

- **USB**：`UsbSerialVcpManager` + `SlcanTransport` → `SlcanManager`；已支持 raw CDC 回退路径时，与连接态判定一致。  
- **蓝牙（若做）**：独立 `BleTransport` 实现同一「发送二进制 / 接收帧」抽象，供 `SlcanManager` 或上层适配。  
- **失败**：Toast + `EngineLog`；不写成功态到 Room。  
- **P18 错误弹窗**：统一从 `Throwable` / 业务错误码映射文案；提供「回到主界面」清空任务栈或 `FLAG_ACTIVITY_CLEAR_TOP`。

## 8. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 单位混用导致圈速错误 | canonical 存储 + 单测换算表 |
| 墙钟模拟圈与真实不同步 | 后续编码器闭环；UI 标注「估算」 |
| 蓝牙与 USB 双通路状态机复杂 | 单一 `Transport` 接口 + 显式互斥或优先级 |
