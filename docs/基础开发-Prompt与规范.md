# DeviceControl — 基础开发 Prompt 与规范

本文档供 **人工开发** 与 **AI 辅助编码** 共用：新会话或新需求开始时，先按本文加载上下文与约束，再改代码。

---

## 1. 项目一句话

**发动机电动转动系统（DeviceControl）**：Android **以平板横屏为主**（与 PDF 一致），同时须 **兼顾手机与不同平板尺寸** 的合理可用布局，见 **§4.1**。技术栈：`app` + `engine-lib`（Kotlin、MVVM、ViewBinding、Room），USB/CAN 控制链路在 `engine-lib` 的 `communication` / `viewmodel` 等包中。

## 3. 开发前必做（Checklist）

- [ ] 确认本需求对应 **PDF 页码** 或 `需求文档-2.0` 章节。  
- [ ] 打开对应 **`page-XX.png`** 做像素/结构对照（布局、按钮层级、文案位置）。  
- [ ] 若动数据或单位：阅读 `技术方案设计-2.0` **§5 数据模型与 PDF 字段映射**；Room 层 **单一 canonical 单位**，换算在 ViewModel/UI。  
- [ ] 若动连接态、顶栏：统一走 **`ConnectionStateRepository`（或技术方案中的单一数据源）**，禁止各 Activity 各写一套判断。  
- [ ] 字符串、单位文案：**走 `strings.xml`**，布局避免硬编码中文。  
- [ ] 对照 `PDF设计稿-待澄清与风险项.md`：涉及「结束/暂停/已连接」等若仍无定稿，实现里写清注释 + 可配置分支，避免静默猜业务。  
- [ ] **尺寸兼容**：见 §4.1；新布局至少在 **手机窄屏 + 10" 级平板横屏** 各走查一遍，无关键按钮裁切、无三栏死叠无法操作。

## 4. 代码与架构约束

| 项 | 要求 |
|----|------|
| 语言与 UI | Kotlin；ViewBinding；横屏与 PDF 一致的业务页保持 `landscape` 策略与现有 manifest 约定 |
| 尺寸与设备 | **手机 + 平板** 宽度与最小边须可接受；禁止仅按单一设计稿像素写死全屏宽；见 **§4.1** |
| 架构 | Activity/Fragment + ViewModel；业务状态进 LiveData/Flow；持久化经 Repository + Room |
| 控制逻辑 | 复用现有 `TaskControlViewModel`、指令映射与 `sendCommandThenPersist` 语义；大改前先拆 PR |
| 资源 | 颜色/圆角/间距优先 `values/colors.xml`、`dimens.xml`、`themes.xml`，少硬编码 |
| 范围 | **只改本需求相关文件**；禁止顺带大重构、删无关注释、改无关模块格式 |
| 风格 | 与周边文件一致：命名、import、协程与空安全习惯与现有 `engine-lib` 对齐 |

### 4.1 手机与平板尺寸兼容（必遵循）

**与 UI 规范一致**：验收条款与三栏策略以 `docs/UI设计规范-2.0.md` **§6** 为准；以下为开发侧摘要。

- **设计原则**：PDF 以 **大屏横屏** 为视觉基准；实现时以 **ConstraintLayout / LinearLayout 权重 / `0dp` + constraint** 等自适应为主，关键区用 **`NestedScrollView` 或 `RecyclerView`** 承接窄屏溢出，避免一屏内无限塞固定高度控件导致小屏不可用。  
- **断点**：按需使用 `values-sw600dp`、`values-sw720dp` 或 `layout-w600dp` 等 **smallest width / 最小宽度** 资源，区分「手机 / 小平板 / 大平板」的列数、边距、是否双栏改单栏（例如检测页三栏在极窄下可改为 **纵向堆叠 + 横向滑动子区** 或 **底部抽屉承载次要栏**，以产品可接受为准，但须 **有明确策略** 而非重叠不可点）。  
- **触控**：主操作区仍满足 **≥ 48dp** 触控目标；缩小字号或间距时不得牺牲误触安全。  
- **字体与密度**：使用 `sp` / `dp`；避免用 `px` 定死布局宽度；长文案 `ellipsize` / `maxLines` 与滚动容器配合。  
- **验证**：交付前至少在 **一款手机（窄，约 360dp 宽）** 与 **一款 10" 左右平板横屏** 上目视 + 点击主路径；复杂页可补 `layout-land` 与 sw 资源各一套，避免维护两套完全重复逻辑时可抽 **共用 include / 自定义 View**。

## 6. 交付与质量

- **自测**：涉及控制页的，在真机或惯用设备上跑通「进入 → 操作 → 返回」；涉及 USB 的保留断连场景。  
- **尺寸**：至少 **手机 + 平板** 各一机（或模拟器对应 sw）验证 §4.1，横竖屏若 manifest 允许则按产品要求抽查。  
- **回归**：不破坏现有 CAN/连续/点动与 Room 成功态写入规则（失败不写成功态）。  
- **文档**：若引入新路由、新全局状态或新 Room 字段，在 `技术方案设计-2.0.md` 或 `需求文档-2.0.md` 用一两句话增量记录（避免口头约定丢失）。
