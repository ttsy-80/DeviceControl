# 2.0 需求 — Android 排期与工作优先级

**角色视角**：安卓高级工程师（Kotlin + MVVM + ViewBinding + `engine-lib` 现状）。  
**需求基线**：`docs/需求文档-2.0.md`、`docs/技术方案设计-2.0.md`；风险与待澄清见 `docs/PDF设计稿-待澄清与风险项.md`。  
**日期**：2026-05-12。

---

## 1. 前提与假设

| 项 | 假设（若不符请自行按比例缩放） |
|----|--------------------------------|
| 人力 | **1 名**资深 Android 全栈本需求；另有 **0.3～0.5 人**产品/嵌入式配合定稿与联调 |
| 联调 | CAN/USB 现有链路可用；**蓝牙走真机联调**若纳入范围则单独加缓冲 |

| 排期单位 | **人日** = 1 人全职 1 天（含自测与 Code Review，不含长假） |

## 2. 工作优先级总览

优先级定义：**P0** 不做则无法按 PDF 主路径演示；**P1** 主路径完整但可简化实现；**P2** 体验增强或可后置。

| 优先级 | 模块 | 说明 |
|--------|------|------|
| **P0** | 全局壳层 | 横屏首页三入口、统一顶栏（时间/日期/连接/电池/标题）、底栏品牌；`ConnectionState` 单一数据源 |
| **P0** | 检测主路径骨架 | P6 型号宫格 → 进入现有 `TaskControlActivity`；**先布局三栏 + 按钮占位绑定旧 VM**，避免「大重写 + 协议一起动」 |
| **P0** | 异常与导航 | P18 风格错误弹层或统一 Dialog；关键失败「回主界面」清栈策略与现有 Toast 并存规则 |
| **P1** | 设置域 | P2～P5：侧栏容器；**先做语言 + 关于 + 手册占位**（WebView/外链）；蓝牙列表与确认连接视产品是否 MVP |
| **P1** | 型号管理 UI | P13 宫格 + 蓝卡新增；P14～P17 在现有 Room/表结构上换皮与交互 |
| **P1** | 自动/手动设置页 | P8 / P11 步进器 UI + 与 `TaskExecution` 映射（含单位换算层） |
| **P1** | LPC 弹层 | P12 列表弹窗与选中回写 |
| **P2** | 系统升级闭环 | P4「检查更新」对接真实升级通道（接口、签名、安装意图） |
| **P2** | 蓝牙协议栈 | 若与 USB 并存：`BleTransport` + 状态机 + 与 `SlcanManager` 抽象对齐（工作量显著） |
| **P2** | 自动拍照 | 权限、触发策略、与记录行绑定（依赖产品细则） |

**执行原则**：**先壳后瓤**（导航 + 顶栏 + 三栏布局先落地），**先 USB 后 BLE**（连接态接口预留），**先 UI 绑定旧逻辑再迁数据模型**（降低一次性回归风险）。

## 3. 阶段排期（建议）

以下为 **顺序依赖** 下的阶段划分；人日为 **单 Android** 粗估，含联调缓冲约 **15%**。

### Phase 0 — 定稿与脚手架（约 3～5 人日）

| 序号 | 交付物 | 人日 |
|------|--------|------|
| 0.1 | 产品确认：结束 vs 暂停、连接态定义、自动/手动与 JOG/CONTINUOUS 关系、单位 canonical | （产品） |
| 0.2 | 工程：`AppShell` / `BasePdfShellActivity` 或 `include` 布局：顶栏 + 底栏 + 内容区 | 2 |
| 0.3 | `ConnectionStateRepository`（USB 现有逻辑迁入）+ 各页订阅样例 | 1～2 |
| 0.4 | `AndroidManifest` 路由、`MainActivity` → `HomeActivity`（或等价）三入口空跳转 | 1 |

**里程碑 M0**：从首页可跳进「设置壳 / 型号壳 / 检测型号选择壳」，顶栏连接态与真机 USB 一致。

---

### Phase 1 — 首页 + 设置域 MVP（约 8～12 人日）

| 序号 | 交付物 | 人日 |
|------|--------|------|
| 1.1 | P1 首页视觉对齐 PDF（文案 `strings`、触控区域） | 1～2 |
| 1.2 | `SettingsActivity` + 侧栏 Nav（或单 Activity + Fragment） | 2～3 |
| 1.3 | P3 语言：持久化 `Locale`/`AppCompatDelegate` + 重启或 `recreate` 策略 | 1～2 |
| 1.4 | P5 关于 + 400 拨号/复制降级 | 1 |
| 1.5 | P2 蓝牙：**UI + 假数据** 或 **扫描 + 配对 MVP**（按产品选一档） | 2～4 |
| 1.6 | P4 升级：展示版本号 +「检查更新」**占位**（Toast/浏览器）或接真实接口（见 P2） | 0.5～3 |
| 1.7 | 操作手册：WebView 加载 assets/URL | 1 |

**里程碑 M1**：设置域可演示；首页与 PDF 信息架构一致。

---

### Phase 2 — 型号管理 2.0 UI（约 6～10 人日）

| 序号 | 交付物 | 人日 |
|------|--------|------|
| 2.1 | P13 `RecyclerView`/`GridLayoutManager` 宫格 + 蓝卡新增入口 | 2～3 |
| 2.2 | 跳转现有型号编辑流；返回栈与「返回首页」一致 | 1 |
| 2.3 | P14～P17 布局与按钮态（编辑/保存/行内添加替换）对齐 ref PNG | 3～5 |
| 2.4 | 导入图片：权限 + `ActivityResultContracts` + 压缩展示（若已有则换皮） | 1～2 |

**里程碑 M2**：型号路径从首页到 CRUD 全流程 UI 对齐 2.0，数据仍走现有 DAO。

---

### Phase 3 — 检测流 + 三栏主控（约 12～18 人日，**关键路径**）

| 序号 | 交付物 | 人日 |
|------|--------|------|
| 3.1 | P6 型号宫格数据源接 Room；选中 → 启动 `TaskControlActivity`（带型号参数） | 2～3 |
| 3.2 | `activity_task_control` 拆三栏：左引擎信息、中表+状态条、右控制矩阵（先绑定现有 LiveData） | 4～6 |
| 3.3 | 模式下拉、LPC 下拉、状态栏文案格式化（ViewModel 输出 String 或 `data class`） | 2～3 |
| 3.4 | P12 LPC 弹层 + 选中回写 | 1～2 |
| 3.5 | 「结束」与「暂停」行为按定稿接 `ViewModel`（停转、持久化、导航） | 2～3 |
| 3.6 | 记录表行操作 UI 与现有记录逻辑对齐 | 1～2 |

**里程碑 M3**：检测主路径可完整跑通（USB），界面与 `page-06`～`page-12` 走查项基本对齐。

---

### Phase 4 — 自动/手动参数页 + 数据模型（约 8～14 人日）

| 序号 | 交付物 | 人日 |
|------|--------|------|

## 5. 依赖与阻塞项

| 阻塞 | 影响阶段 | 缓解 |
|------|----------|------|
| 自动/手动与 JOG/CONTINUOUS 未定 | Phase 3～4 | Phase 0 书面定稿；否则先 UI 双下拉绑定旧枚举 |
| 蓝牙是否替换 USB 为主通道 | Phase 1、3 | 默认 USB 真连接态；蓝牙仅 UI 或独立分支 |
| 升级接口与签名策略未定 | Phase 1 P4、P2 | 长期可外链；短期占位 |
| 嵌入式确认「结束」安全顺序 | Phase 3 | 与固件同事联合签一页状态机 |
